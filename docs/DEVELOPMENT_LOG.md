# 开发日志

## 2026-11-18

### v1.2.1 — 方向性躲闪、桌面常驻、无缝出缸

**1. 躲闪按方向来，更像真的**

- 鼠标迎面（在鱼头朝向一侧）：**C 型惊跳**——身体一拍之内甩过来（heading 直接
  甩到逃跑方向），往回逃。鼠标从背后偷袭：不转身，**加速向前冲**。
- 再快一档：速度 ×4.2（原 3.6）、加速度 ×3.5、时长 0.45 → 0.4s、冷却 1.4s。
- simtest 新增两条断言：迎面 → 朝向反转（cos(Δheading) < -0.5）；背后 →
  朝向不变且目标点沿原航向（cos < 0.9 的夹角内）。

**2. 鱼缸最小化后，桌面鱼留在桌面上（真 bug）**

- 症状：鱼"跑到屏幕左上角然后自动回鱼缸"。根因：最小化的窗口被 Windows 报告
  在 (-32000,-32000)，回缸目标被钳到桌面角 (24,y)，鱼游到角上触发 rescue 被
  丢回缸里。
- 三处修复：①**取消边界开启时的自愿回缸**——游出去的鱼只有渔网或关门才能
  带回家（顺带把回缸冲刺 1.7 → 2.1×，远鱼回家不用一分钟）；②鱼缸隐藏/最小化
  但边界开着时**模拟继续跑**（桌面鱼照游、照常躲闪和好奇），只有"边界关闭 +
  窗口隐藏"才停循环；③最小化时跳过位置同步，保住上一个有效的窗口矩形。
- 桌面层握手超时 3s → 6s：冷启动的 WebView2 偶尔超时导致开边界失败。

**3. 出缸不再割裂**

- 旧行为：鱼中心出界才切换画布，鱼头先顶出缸边、被画布裁掉 1-2 秒，然后
  整条鱼"弹"到桌面上。现在**行进方向的前端一过缸边就切换**：桌面层（盖在
  鱼缸之上）直接画整条鱼，交接帧 mix=0 还是墨黑，接缝不可见。
- 顺带修掉一个隐藏 bug：回缸目标在缸内 42px，而入缸交接要求整个字形进缸
  （46px）——鱼会停在目标点差 4px 永远触发不了交接，2.5 秒后被 rescue
  瞬移回缸（simtest 抓到 487px 一跳）。所有回缸目标统一为 `halfW+8` 深。

**测试基础设施**：p2smoke 的"点一次暂停/边界"改为带效果验证；"补点一次"的
旧逻辑会在回缸途中把边界重新打开（RETURNING 再点 = 重新打开），改为"鱼群
有没有开始回家"判定；overlay 几何检查改为等待就位；拖框手势加预热按住 +
中间步进（首个点击要把焦点交给透明层）。

**验证**：simtest 81 项（10 轮种子稳定）；p3test 49 项；p2smoke 26 项
（8/8 连跑）。

## 2026-11-17（续二）

### v1.2.0 — 自适应颜色、更快的躲闪、鼻尖嘬、自定义小鱼

**1. 桌面鱼的颜色跟着背景走，画得更粗**

- Rust 新增 `screen_pixel` 命令（GetPixel 读合成桌面），鱼缸每 ~400ms 轮询一条
  桌面鱼的背景（round-robin），鱼对亮度做 0.2 系数平滑。
- 深色背景（亮度 < 90）：鱼身颜色向白色提亮最多 55%；亮色背景（> 210）略压暗。
  墨色同样自适应：**回缸淡出的"墨"在深色桌面上是浅灰、在亮色桌面上是近黑**——
  这修复了"鱼在左上角消失"：那是回缸鱼在深色壁纸上淡成纯黑，肉眼看不见，过
  一阵重新出门才"再出现"。现在整个淡出过程都可见。
- 色板整体换亮（橙 #E8823C / 蓝 #3E8CDC / 青 #2CA894）；桌面鱼在粗体之上再加
  四个 ±0.6px 的错位描边——像素实测核心墨量又涨一截。
- p2smoke 的像素检测器同步重写：固定 RGB 目标 → **沿提亮线取 6 个参考点、
  容差 16**（太宽的色相判定会把 VSCode 语法高亮当鱼：一次抓到 22 个假簇；
  桶内最小像素 60 → 100 滤掉 UI 碎片）。

**2. 朝向俯仰与躲闪**

- 俯仰基准 3.2 → 5.5px（随尺寸缩放），游斜线时鼻尖明显上翘/下潜；巡航的水平
  拉回 0.35 → 0.22，斜向行程更多。
- **躲闪改成真正的惊跳**：速度 ×3.6（原 2.2）、加速度 ×3、转向速率 ×2.5、
  时长 0.75 → 0.45s、冷却 2.2 → 1.6s。实测 0.8s 内拉开 ~50-70px，肉眼可见的
  一蹿。

**3. 嘬鼠标：鼻尖对着鼠标**

- 旧实现鱼的重心停在光标上——对着鼠标的是鱼肚子/眼睛。现在好奇接近的目标是
  "鼻尖落点"（光标 + 朝向 × (半宽-5)），嘬的第一拍是一记滑铲把剩余距离一次
  扑掉（最多 ~26px），之后 2-4 下小幅啄动，鼻尖贴着光标。
- 过程中修了两个真问题：①快鱼以 55px 转弯半径绕光标打转、永远进不了 8px 触发
  区——加了**到达刹车**（70px 内速度线性降到 30%）；②鱼群围观光标时分离力把
  来嘬的鱼挤开——专注状态（躲闪/好奇/嘬）豁免分离力。③正在嘬的鱼不会被
  "自愿回家"定时器拽走（returnAt 顺延 8s）。

**4. 自定义小鱼**

- 设置面板新增输入框 + 「添加 / 头朝右左 / 移除」。输入的字符就是鱼（最多
  16 字符），默认头朝右（可切头朝左）。自定义鱼游在标准鱼群之外（数量滑杆
  只管标准鱼群——这里修过一个真 bug：数量裁剪曾把标准鱼和自定义鱼各删一次）。
- 字形方向由 GlyphRun 的可选 `canonFacing` 覆盖（内置字形仍从首字符推导），
  两个渲染器的缓存键升级为 `字形@尺寸@朝向`；镜像规则照常（镜像表有的字符
  镜像，没有的仅反序）。设置新增 `customGlyph` / `customFacing` 两键（共 8 键）。

**验证**：simtest 76 项（20 轮种子稳定）；p3test 49 项（5 轮全过，含自定义鱼
全流程与真实窗口里的躲闪/嘬）；p2smoke 26 项（真实鼠标 + 新检测器）；
p5test 待新版安装包构建后跑。

## 2026-11-17（续）

### v1.1.0 — 鱼鼠交互、框选捞鱼、可调鱼群

四项新功能，全部在真实程序上验证过：

**1. 鱼鼠交互（躲闪 + 好奇嘬鼠标）**

- 光标靠近（46px 内）且最近移动过（2s 内），鱼会**快速躲开**：一条 ~150px 的冲刺
  （速度 ×2.2），0.75s 后恢复巡航，2.2s 内不再重复触发。
- 光标**久放不动**（默认 ~4s，随活泼度缩短）时，游到附近（~70px）的鱼会**好奇地
  凑过来**，到达后连续"嘬" 2–4 下（0.26s 一嘬的快速前冲），然后离开，12–20s 内
  不再回来。
- 只在鱼"自由巡航"时触发：正在出缸/回缸的鱼不受打扰。**捞鱼模式下躲闪暂停**——
  网都拿出来了，鱼得乖乖被框。
- 光标数据：缸内用真实 pointermove 事件；桌面上由鱼缸窗口每 100ms 轮询
  `cursor_pos`（只在边界开启时）。光标进入视野的第一帧记为移动（否则 idle 会是
  Infinity，鱼会对着刚出现的鼠标就开嘬——simtest 抓出来的）。

**2. 捞鱼改为框选（拖网）**

- 旧的"点击单条鱼拖回缸"整条链路删除（`grabFish/dragFish/dropFish`、overlay 的
  拖拽事件、dragging 状态）。
- 新交互：点「捞鱼」→ 桌面层接管整个屏幕的鼠标（任务书本来就允许的显式模式）→
  按住拖动画一个框（白边黑芯，深浅桌面都可见）→ 松手 → **框里的鱼全部开始游回
  鱼缸**（`lassoFish`，不瞬移，走 returning 流程）。单击也算一张 16px 的小网。
- 收网：**Esc 或右键**（overlay 页面处理，emit 回鱼缸），窗口失焦也自动收网——
  捞鱼模式永远不会把用户锁死在透明层里。捞鱼时桌面底部有一条提示。
- 捞鱼模式期间透明层全屏接住鼠标；收网立即恢复穿透（p2smoke 用 WindowFromPoint
  验证了这四个状态）。

**3. 鱼群可调（设置面板三个滑杆）**

- 数量 3–8（默认 5）：多出来的鱼复用三种字形，颜色按色族取不同深浅
  （橙/蓝/青各 3 档），速度 ±8% 抖动，id 唯一（`fish-a-1`、`fish-b-2`…——
  id 重复会让按 id 寻鱼的测试和捞鱼全部错乱，simtest 抓出来的）。
- 大小 12–22px（默认 15）：两个渲染器的 runs 缓存按 `字形@尺寸` 键控，
  半宽半高、波幅、命中盒全部随尺寸缩放，快照里带 `size` 字段。
- 活泼程度 0.5–2.0（默认 1）：速度倍率 + 好奇心（越活泼，静置阈值越短、
  吸引半径越大）。
- 三个值都进 settings.json（现在共 6 个 key，p5test 验证过滑杆改值→落盘→重启读回）。

**4. 游出方向：只走左右两侧**

- 出缸目标从"最近边"改为"**朝向的那一侧**"：`x = w+30 或 -30，y 钳在缸内 34px
  以上`——鱼朝自己面对的方向水平游出，不再从上方或下方漏出去。
- simtest 断言了每个交接帧的出口位置和朝向。

**顺带修掉的三个真 bug（都是测试抓出来的）**

1. **跨界中断的 40px 瞬移**：鱼游到缸边准备出去时用户合上边界，`keepInside` 硬钳位
   把鱼弹回 40px。现在"已经在门口的鱼"完成越界后立刻折返（resolve 里按边界状态
   决定 outside/returning），跨界中的鱼豁免硬边界，全程连续。
2. **入缸钳位瞬移**：回缸交接原来在鱼中心一过缸边就发生，`enterTank` 的入缸钳位
   造成 ~46px 的跳变（旧测试跳过了交接帧所以没暴露）。现在等**整个字形完全进入
   鱼缸**才交接（负 pad 的 rectHas），钳位降到 ≤2px，接缝依然不可见（交接时已是
   墨黑）。
3. **`setCursor` 的 idle 时钟**：首次上报光标不记移动，idle 从 -Infinity 起算。

**验证**：simtest 67 项（新增躲闪/好奇/框选/出口方向/设置五组；20 轮连跑全过，
种子稳定）；p3test 44 项；p2smoke 26 项（真鼠标框选一条鱼，4.25s 后它离开原地
游回家；右键收网）；p5test 设置部分 15 项。

## 2026-11-17

### Phase 0 — 环境与可行性

- 环境巡检：Node 22.22.2 / npm 10.9.7 / MSVC 14.50 + Windows SDK 26100 / WebView2 148 都在，
  **唯独没有 Rust**。
- 安装 rustup 1.100.0（minimal profile，x86_64-pc-windows-msvc），验证 MSVC 链接可用。
- 起项目骨架：不用模板，不用打包器。
  - `package.json` 只有一个 devDependency（`@tauri-apps/cli`）。
  - `tauri.conf.json`：`devUrl` 指向 `scripts/dev-server.mjs`（自带 http 服务，零依赖），
    生产走 `frontendDist: ../src`。
  - `withGlobalTauri: true`，前端用 `window.__TAURI__` 直接调命令/订阅事件。
- 写 `overlay.rs`：透明窗口按 `SPI_GETWORKAREA` 摆位、置顶、跳任务栏、默认穿透。
- 写 `techcheck.rs`：12 项自检，全部用系统 API 回读，不用"应该可以"。
- 写 `win32.rs`：手写 12 个 Win32 声明（窗口矩形、工作区、`WindowFromPoint`、`GetPixel`、
  DPI、ExStyle），**没有引入 windows-sys**。
- 图标用 `scripts/make-icon.py`（Pillow）画一只 `><(((o>`，再 `tauri icons` 生成全套。

踩坑与决策：

1. **从命令里建窗口死锁。** 命令里直接 `ensure_overlay()` 会卡住不返回；
   套进 `run_on_main_thread` 也一样（`build()` 内部投递并等待事件循环，等于等自己）。
   改为在工作线程里发起创建。已在代码和架构文档里写清楚原因。
2. **隐藏 ≠ 停止。** 透明层 `hide()` 后仍留着一个 renderer 空转（+4% CPU / 70MB）。
   改成 `destroy()`，并给 `overlay.js` 加了 `visibilitychange` 停帧。
3. **`GetWindowRect` 比视觉窗口大 ~7px**（不可见边框），像素比对必须按内容区裁剪，
   否则会把桌面背景的变化算进差分。

### Phase 1 — 基础鱼缸

- 结构按任务书的模块划分：`simulation` / `fish` / `fish-behavior` / `aquarium` /
  `bubbles` / `seaweed` / `settings` / `main`。`coordinates.js` 留到 Phase 3 再建
  （现在没有真实用途，不写死代码）。
- 运动引擎：单一 rAF 循环 + 时间差推进 + 帧预算跳帧；暂停/隐藏直接停循环。
- 鱼的行为：游荡目标（每 0.8–5.4s 重掷）+ 避墙力 + 邻鱼排斥，用**转向速率上限**混合，
  所以没有瞬变；硬边界只做兜底。
- 首版截图发现两个问题，都当场改掉：
  1. 海草像"大头针"——直的茎 + 游离的 `╱`。改成"高度平方的弯曲 + 局部斜率选字"，
     并按簇分布（0.085 / 0.33 / 0.625 / 0.885），不再是一条栅栏。
  2. 两条鱼会叠字。排斥半径 46 → 62，权重 1.7 → 2.4。
- 设置面板做了最小可用集：海草 / 气泡 / 高帧率 60 / 透明层自检。
- 性能：`ctx.font` 只在变化时赋值；默认目标改 30fps（任务书的目标值），
  失焦降到 24fps，60fps 变成需要手动打开的选项。
  实测 30fps 单核 11.9%、60fps 17.4%、暂停 0%。

### 测试方式说明

界面上没有留任何测试后门。测试靠外部脚本（`scripts/grab.py` + 一段 Win32 注入代码）：

- 截图差分判定"暂停是否真的静止"（暂停 2.2s 内 0 px 变化，恢复后 8424 px 变化）。
- `WindowFromPoint` 判定"点击到底落到谁头上"，这是穿透测试的唯一可信依据。
- 像素 A/B（显示/隐藏透明层）判定"背景是否真的透明"。
- 键盘注入被环境的安全策略拦了，所以空格/Esc 只做了代码审查，测试报告里如实标注"未验证"。

### Phase 2 — 桌面透明悬浮层

结构变化：

- `coordinates.js`：桌面坐标空间、颜色混合、矩形几何。鱼在缸里用缸内坐标（跟着窗口走），
  出了边界换成桌面坐标（留在屏幕上），越界/回缸各转换一次。
- `desktop-overlay.js`：鱼缸这一侧的桌面层控制器（创建/销毁/握手/推帧/捞鱼开关），
  与桌面层的通信只在这里发生。
- `overlay.js` 重写：不再自己造鱼，只收 `tank-frame` 快照并画；有变化才重绘。
- `simulation.js` 扩成"一个世界两个空间"：`boundary` 开关、`decide()`（越界/回缸意图）、
  `resolve()`（换空间）、`snapshot()`（喂桌面层）。
- `fish.js` 增加 `space` / `state` / `colorMix` / `goal`，`update()` 在世界对象里拿
  `hardBounds`（边界打开时关掉硬夹取，鱼才出得去）。

关键决策：

1. **单一大脑。** 桌面层不持有鱼，只画。这样"不瞬移/不重复/不消失"是模型自带的性质，
   不靠跨窗口同步去兜。
2. **交界处一帧切换画布。** 缸内鱼由鱼缸画、缸外鱼由桌面层画；越界那一帧 `colorMix=0`
   （还是墨黑），所以换画布这件事看不出来。
3. **销毁而不是隐藏桌面层。** 沿用 Phase 0 的结论；再次打开时用"ping/pong 握手"确认页面
   真的在听，握手完成前不发放外游意图（避免鱼游进一块还没准备好的玻璃）。
4. **捞鱼模式按距离动态切穿透。** 不是整屏接管：每 55ms 问一次光标，只有靠近鱼才可命中。
5. **回程加速。** 有目标时速度 ×1.7、加速度 ×1.6，往返从 19 秒缩到 7 秒，仍然是连续游动。

踩坑：

1. **`overlay_show` 同步命令把事件循环等死。** Phase 0 的坑又踩了一次——新写的命令没有
   照抄"在工作线程建窗口"的结论。改成 async + `spawn_blocking`，并在 `overlay.rs` 注释里钉死。
2. **快照漏字段。** `sim.snapshot()` 只发了 `id/x/y/facing/mix/color`，没发字形；
   桌面层 `fillText(undefined)`，于是"鱼出来了但看不见"（计数还是 3）。
   加 `g: fish.glyph` 后立刻正常。教训：跨窗口传的东西，用日志把真实内容打出来看。
3. **两个鱼缸。** 测试时旧进程没杀，同时跑了两个实例——屏幕上两套鱼。
   产品侧补了单实例 mutex（第二个实例把已有窗口提到前台后退出）。

### 交付前的整链路冒烟测试（`scripts/p2smoke.py`）

Phase 2 之前是逐项点出来的，重跑一次就得重新拼。补了一个可重复的整链路脚本：
启动 → 找到窗口 → 点「打开边界」→ 校验透明层几何 → 等鱼出缸 → 暂停 → 点「捞鱼」→
`WindowFromPoint` 三态判定 → 关边界 → 校验透明层已销毁。25 项，全绿才返回 0。

做这个脚本本身踩的坑（都不是产品 bug，是"测量方式"的坑，值得记下来）：

1. **坐标不能猜。** 窗口有原生标题栏，`GetWindowRect` 又比视觉窗口大 11px。
   一开始把屏幕上的长横线当成鱼缸边框——结果抓到的是浏览器里的线。
   改成 `GetClientRect + ClientToScreen` 拿客户区原点，在客户区里找"最长的连续墨线"，
   再把换算出来的 scale 和配置里的 760 CSS px 对账（1.750）。从此不依赖窗口摆在哪。
2. **空列表不等于静止。** 鱼在缸边淡出时检测不到，两帧都空就被当成"暂停生效"，
   于是根本没点暂停，后面瞄的是一个还在游的目标。改成：空列表返回"不知道"，
   要同一批位置前后一致才算停住。
3. **点完「捞鱼」光标还停在按钮上。** 断言却去看鱼身上那个点——永远不会命中。
   改成每次尝试先把光标放回鱼身上再判定。这一条害我以为产品坏了三次。
4. **穿透状态会影响点自家按钮。** 捞鱼模式下光标刚离开鱼，透明层还吃着鼠标，
   这一瞬间点鱼缸按钮会落空。所以点按钮前先移过去、等一个轮询周期（55ms），
   确认 `WindowFromPoint` 已经回到鱼缸再点。
5. **桌面不是真空。** 期间用户在用机器，前台窗口一会是浏览器一会是编辑器，
   截图里根本没有鱼缸。加了"窗口确实在最前"的前置判定，不满足就整轮作废（退出码 2），
   而不是拿别人的界面当鱼缸去断言。
6. **`cargo build` 和 `tauri build` 不是一件事。** 直接 `cargo build` 出来的是 dev 版 exe，
   它去连 `devUrl`（127.0.0.1:5183），dev server 没起来就是一块黑窗口（页面没加载，
   连按钮都测不到）。交付和测试一律用 `npx tauri build --debug --no-bundle`。

三次连跑：25/25、25/25、25/25。

### Phase 3 — 鱼缸与桌面之间的自由切换

Phase 2 已经能开关边界，但鱼的运动读起来像"漂"，不像"游"。这一阶段先把这件事解决，
再把坐标、状态、颜色的边角补齐。

**运动模型：从"随机转向"改成"游向某个地方"**

旧模型每隔一两秒给 heading 加一个随机角度。角度随机游走 = 布朗运动 = 看起来没有目的。
新模型每条鱼维护一个 `cruise` 目标点（离自己至少 240px，或鱼缸 40% 宽），朝它游；
到达（<34px）或超时（每条鱼 0.8–5.4s）才换一个。heading 仍然受 `turnRate` 限制，
所以转弯永远平滑；`Math.sin(pitch)` 直接来自 heading，头自然朝着行进方向。

**字形布局：一条线段转不了，但可以弯**

`src/js/glyph.js` 把一串字符拆成逐字符的 `(dx, dy)`：

```
u    = i / (n-1)                       0 = 头，1 = 尾
wave = sin(phase - u*3.1) * amp * (0.25 + 0.75u)
tilt = sin(heading) * 3.2 * (0.5 - u) * 2
dy   = wave + tilt
```

尾部摆幅是头的四倍，所以头几乎不动、身体在扭——和真鱼一样。`phase` 按
`bobSpeed*1.6 + speed*0.05` 推进，快鱼摆得快。俯仰让头在向下游时低于尾巴，
这是"头朝哪就游向哪"最直接的视觉证据。两个画布用同一份布局，所以穿边界时形状不变。

**这一阶段抓到的 bug（都不是猜出来的）**

1. **字体缓存和画布重置不同步。** `resize()` 里给 `canvas.width` 赋值会重置上下文的
   全部状态，包括 `ctx.font`，但渲染器缓存的 `currentFont` 还写着"已经设过 15px"。
   结果：字形按 8.79px 排布、却用 10px 的字画出来——一条鱼看起来像被拉开的项链。
   这是改成逐字符渲染后才暴露的。在 `resize()` 里清空缓存。
2. **`Infinity < 34` 是 false。** cruise 为 null 时 `toTarget` 是 Infinity，条件不成立，
   于是既不去选目标、又在下一行读 `this.cruise.x`——空指针。`node scripts/simtest.mjs`
   第一次跑就崩在这里。判断里显式加上 `this.cruise === null`。
3. **pitch 用的是转弯前的 heading。** 每帧先算 pitch 再转向，肉眼看是鱼身比运动方向
   慢半拍。改成转向之后再取。simtest 断言 `pitch === sin(heading)` 抓到的。
4. **被遮挡就停摆。** Chromium 认为窗口没人看得见时会节流 `requestAnimationFrame`。
   鱼缸被浏览器最大化挡住时，桌面上的鱼会一起僵住——因为模拟跑在鱼缸窗口里。
   两个窗口都加 `--disable-backgrounding-occluded-windows --disable-renderer-backgrounding`。
   这是设计缺陷，不是性能优化。

**坐标加固**

- 回缸目标先算"缸内离鱼最近的点"，再钳到桌面内（±24px）。缸挂在屏幕边缘时，
  鱼不会被引到屏幕外。
- 如果钳制之后目标根本进不去（缸几乎完全出屏），鱼会在目标附近停住。给它 2.5s，
  还进不去就 `rescue()`：直接放回缸内中心附近。这一跳只可能发生在缸本身看不见的时候，
  用户看不到，但避免了"回缸永不完成 → 透明层永不关闭"的死状态。
- 拖动窗口/改窗口大小时 `onMoved`/`onResized` 触发重新测量；回缸中的鱼每帧重算目标，
  所以把缸拖到鱼身上时鱼会立刻进缸。

**连续切换**

回缸过程中，按钮不再是禁用的"回缸中…"，而是"重新打开"——点了就取消回缸
（`openBoundary()` 会把 returning 的鱼改回 outside）。人想反悔时第一反应就是再点一次，
禁用按钮只会让人以为程序卡住了。

**颜色**

淡入仍是 1.8/s。淡出改成按"离缸边的距离"连续映射：32px 内为 0，142px 外为 1，
中间用 smoothstep。原来的二值阈值（96px）会在鱼横穿那条线时闪一下。

### Phase 4 — 捞鱼交互、稳定性与性能

**拖动链路：只传意图，不传结果**

```
overlay: pointerdown → 命中鱼 → emit overlay-grab
tank:    grabFish(id) → state = "dragging"
overlay: pointermove → 本地画在指针处（不等 30Hz 快照）→ 每 16ms emit overlay-drag
tank:    dragFish(id, x, y) → 位置、朝向（拖动方向）
overlay: pointerup → emit overlay-drop（桌面坐标）
tank:    dropFish(id, x, y) → 落在缸内 enterTank（立即变黑）；落在桌面 → outside，18s 内不再自己往回游
```

桌面层的拖动是本地即时绘制的：等 30Hz 快照回来再画会有"拖影"，而鱼的权威位置仍在
tank 里。松手后两边在下一帧对齐。

兜底：2.5s 没收到拖动事件（层被销毁、鼠标丢了、程序被挂起）就把鱼放下，
不会把它冻在半空。拖动期间光标轮询始终让层保持可命中，松手立刻回到"靠近鱼才接住"。

**性能：先量，再改**

一开始想把"鱼缸重绘"干掉，结果测下来不是瓶颈。最后做的四件事：

1. 水草/气泡/砂砾画到离屏画布，14Hz 刷新（100 个字形 30Hz 重画没有必要）。
2. 鱼用脏矩形：只擦上一帧鱼所占的方框，再从离屏背景把那块补回来。全画布 clear + blit
   是这一层最贵的事。
3. 桌面层只清/画有墨的矩形（之前是全屏 clear）。
4. 没有鱼在桌面上时根本不发帧（之前 30Hz 发空数组），桌面层的 rAF 也随之停掉。

实测（锁屏 + 机器上有别的负载，`python scripts/perf.py`）：

| 模式 | CPU（单核占比） | 内存 | 进程 |
|---|---|---|---|
| 鱼缸模式 | 16.1% | 375 MB | 7 |
| 桌面模式（1 鱼在外） | 38.8% | 476 MB | 8 |
| 暂停（循环完全停止） | 5.3% | 386 MB | 7 |

暂停的 5.3% 是这套架构的地板价：一个 WebView2 窗口即使什么都不画，也要被 DWM 合成。
也就是说"画三条鱼"大约值 11% 单核，第二个透明全屏窗口再值 20% 左右。
进一步压缩只能换渲染方案（比如单窗口 + WS_EX_LAYERED 直接画），那是另一个工程，
不在这一版的范围里；数字如实记在 TEST_REPORT 第 29 节。

### Phase 5 — 打包与交付

**设置落盘**

`%APPDATA%\TextAquarium\settings.json`（Rust 写，先写 `.tmp` 再 rename，避免写一半）。

**安装包**

NSIS，`installMode: currentUser`——不需要管理员权限，实际装到
`%LOCALAPPDATA%\Text Aquarium`（不是 `Programs` 子目录，构建前我以为会是，

产物：`src-tauri/target/release/bundle/nsis/Text Aquarium_1.0.0_x64-setup.exe`，
1.1 MB；解出来的程序本体 3.1 MB，前端资源全嵌在 exe 里，不再依赖 devUrl。

SHA-1。这条写进 README 了。

**验收**

`python scripts/p5test.py` 20 项全过（TEST_REPORT 第 30 节）：设置改一次→落盘→重启
读回；安装包静默安装→开出窗口→卸载→注册项清干净→设置文件还在。其中一项专门证明
"交付版不是开发版"：把开发用的 `cmd-tank.js` 丢进 dump 目录，装好的程序 9 秒内毫无反应
（测试钩子只在 `127.0.0.1` 上安装，打包后的页面是 `tauri://localhost`）。

**长跑**

第一版 `soak.py` 用"首尾差值 > 25 MB 就算不稳"判定，结果 6 分钟报了 +64 MB 不稳定。
分进程、分阶段复测后发现那是预热：一个 WebView2 窗口的合成层是懒分配的，前 1.5 分钟
涨 15 MB 然后走平；透明全屏那一层涨到第 4 分钟才平。于是 soak 改成"先预热 3 分钟，
再量斜率"，判据换成 MB/min。结论与数字见 TEST_REPORT 第 29 节。

**关于那次"进程消失"**

一套 soak 跑到 15.6 分钟时进程树整体没了，页面也不再应答。查了应用事件日志、
CrashDumps、代码里的 `exit` / `close`，都没有痕迹；反过来做对照——只启动、开一次边界、
之后 20 分钟不碰它——进程好好活着。结论是测试脚本之间互杀（每个脚本都以
`taskkill /F /IM text-aquarium.exe` 开头结尾，两套并行就会互相打断）。
`soak.py` 现在遇到这种情况会直接说"the app disappeared after N min"并去事件日志求证。

**没有测到的**

`p2smoke.py`（真实鼠标 + 屏幕像素）整夜没法跑，机器一直锁屏。11-17 上午解锁后立刻补跑，
在最终代码上 25 / 25 通过（TEST_REPORT 25.3）。顺带一个和运动重做直接相关的数字：
关边界到桌面层销毁从 4.11–6.50s 降到 **0.89s**——鱼不再随机漫步，而是朝缺口直线游。
剩下的未测项（多显示器、一整天、无 WebView2 的老系统等）列在 TEST_REPORT 第 31 节。

### 11-17 下午 — 三项视觉修复（接手后的第一轮）

**1. 鱼转身被撕碎（真 bug）。** `glyph.js` 的 `layout()` 只把字符*位置*镜像（`dx × facing`），
字符本身既不反序也不镜像：左游时鼻子跑到身体右侧还指着右，`><)))o>` 变成一摊 `>o)))<>`。
改成**整鱼调头**：字符反序 + 逐字符镜像（`>`↔`<`、`(`↔`)`、`彡`→`ミ`）。字形串自带方向
（首字符 `>` 右向、`<` 左向），`facing` 与字形方向不符时改用镜像串；波纹与俯仰按"鼻端"锚定
（镜像时 u 取 1-t），所以左游时鼻子在右端、波纹仍从鼻传到尾。实测 `><)))o>` 左游 =
`<o(((><`（用户给出的理想形），fish-c 右游 = `ミ(((°>`。两个渲染器统一从
`GlyphRun.drawChars` 取字，快照协议不用动。

**2. 往前游为主，少上下浮。** 先测量（headless 跑 120s 模拟）：旧行为 vy/vx ≈ 0.8，
陡角航向时间 ~40%，尾摆 ±6.1px（15px 字号）。两处改动：

- `pickCruise` 从"二维均匀随机点"改成"沿当前航向 ±52°、向最近水平方向拉回 35%"——
  换目标是修正航向，不是 U 形掉头。旧模型下 fish-b/c 每 1.3–2.8s 就重掷目标，永远在
  转向途中，航向分布近乎均匀，这就是"上下浮动多于前后移动"的根因（直方图证实）。
- 波幅 `bobAmp × 2.1 → × 1.2`，航向摆动 ±0.35 → ±0.18 rad。

改后实测：vy/vx 0.44–0.58，陡角时间 14–23%，巡航时波纹只有 ±1.2–1.7px（剩下的尾摆
来自竖直游动时的俯仰，那是"头朝哪游向哪"的线索，保留）。

**3. 桌面鱼加粗。** 桌面层在常规字重上叠一层 bold 通道，透明度 = `colorMix`：加粗随
颜色渐入（约 0.6s），回缸时随褪色渐出，进缸前已恢复细体——缸内永远是墨黑细体。
像素证据：桌面全色鱼在真实抓屏里的核心像素从旧版的 154 涨到 269–395（约 2.5 倍）。

**验证**：simtest 44→50 项（新增整鱼镜像断言，并把 toggle 测试的位移测量改成跨空间
补偿——它原先用原始坐标做差，把跨界转换的 ±(200,150) 偏移误判成 251px 瞬移；新运动
模型下鱼游得快，跨界赶上了采样帧才暴露）；p3test 39/39；p2smoke 25/25。

**两个测试基础设施修正（都是今天实测发现的）**：

1. p2smoke 原先"发现鱼簇就暂停"，鱼还在淡入（m≈0.85）就被冻住，颜色被洗淡、检测器
   只数到 87px；改为等 ≥150px 的实心鱼簇出现再暂停。
2. 本机的 debug exe（`cargo build` 与 `tauri build --debug --no-bundle` 是同一产物）
   是 dev 模式、页面走 devUrl：p2smoke 之前能 25/25 是因为 dev server 恰好活着。
   现在 p2smoke 与 p3test 一样自动 `ensure_dev_server()`。真正独立运行的只有 release
   产物（安装包）。README 里"tauri build --debug 是独立 exe"的旧说法与实测不符，已改正。
