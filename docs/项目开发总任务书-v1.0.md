# Text Aquarium
## 项目开发总任务书 v1.0

**项目名称：** Text Aquarium（文本鱼缸）  
**项目类型：** Windows 桌面轻量宠物应用  
**核心理念：** 一个可以从文字世界游进真实电脑桌面的微型生态。  
**开发原则：** 极简、低打扰、低资源消耗、无需照料、长期运行。

---

# 一、项目背景与愿景

我要开发一个属于自己的小宠物系统。

它不是传统的电子宠物，不需要喂养、升级、完成任务，也不需要每天登录。它只需要安静地存在、自由活动，偶尔让我观察。

宠物选择鱼。

打开程序后，首先看到的是一片纯白色的页面。这个页面就是一个小鱼缸。

鱼、海草、气泡等元素都由文本字符组成。小鱼以类似 ASCII Art 的方式呈现，例如：

`><(((o>`

小鱼可以在鱼缸内部自由游动，有自己的速度、方向和简单的行为。

但这个鱼缸还有一个特殊机制：

**鱼缸的边界是可以打开的。**

打开边界后，小鱼能够从文本鱼缸中游出来，进入电脑桌面。进入桌面世界后，小鱼会由黑白字符变成彩色字符，并能够在其他软件窗口上方自由游动。

此时，鱼缸变成了整个电脑桌面。

用户可以观察它们，也可以通过鼠标把它们捞回来。关闭边界后，鱼会逐渐返回鱼缸。

这是本项目最核心的体验，不能将它简化成两个互不相关的页面或两个独立的宠物系统。

# 二、核心产品原则

1. **低维护：** 鱼不需要喂养，不会饥饿、生病或死亡。
2. **自主性：** 即使用户不操作，鱼也会持续活动。
3. **无压力：** 不设置签到、任务、成就、提醒等游戏化机制。
4. **轻量化：** 不需要账号、服务器、数据库或网络连接。
5. **视觉统一：** 整个项目坚持文本字符风格，不能突然变成复杂的卡通游戏。
6. **真实交互：** 鱼必须拥有连续的位置和运动状态，不能通过瞬移假装游出鱼缸。

# 三、视觉设计规范

## 3.1 鱼缸模式：黑白文字世界

视觉要求：

- 背景：纯白色 `#FFFFFF`
- 文字：纯黑色 `#111111`
- 边界：细黑色线条
- 字体：等宽字体，优先使用系统 Monospace 字体
- 不使用渐变、阴影、纹理、复杂插画
- 不使用照片或外部素材
- 不使用彩色 emoji 作为主要视觉元素

鱼缸中的主要元素全部使用字符绘制。

参考：

小鱼：

`><(((o>`

`<°)))彡`

`><(((*>`

气泡：

`o`

`°`

`○`

`·`

海草：

`♧`

`│`

`╱`

`╲`

`〰`

以上仅为字符风格参考，可以适当调整，让不同元素看起来更协调。

鱼缸不应该充满文字，必须留出大量空白，让它有宁静、自由的感觉。

## 3.2 桌面模式：彩色文字世界

当小鱼离开鱼缸，进入电脑桌面时：

- 小鱼的字符造型保持不变。
- 小鱼由黑白变为彩色。
- 不同的小鱼拥有不同的颜色。
- 不使用写实鱼类图片或复杂 3D 模型。
- 仍然以字符、文字和简单线条为主要视觉表现。

建议采用低饱和度的颜色，例如橙色、蓝色、青绿色。

鱼缸中只能出现黑白元素，桌面上的鱼才拥有颜色。

## 3.3 基本界面布局

鱼缸初始窗口建议约为 760 × 480 px。

界面结构：

- 简洁的顶部区域：程序名称和必要控制。
- 主体：鱼缸。
- 鱼缸内部：小鱼、海草和气泡。
- 边界：明确显示鱼缸范围。
- 底部：可以显示少量状态信息，但不要喧宾夺主。

控制按钮包括：

- 边界开关
- 暂停 / 继续
- 捞鱼模式
- 设置
- 关闭或最小化

这些控制应当尽可能简洁，不要设计成复杂的游戏菜单。

# 四、核心功能需求

## 4.1 鱼缸窗口

程序启动后，打开独立的鱼缸窗口。

要求：

1. 默认显示白色背景。
2. 默认边界关闭，小鱼不能离开鱼缸。
3. 小鱼自主游动。
4. 鱼缸中存在海草和气泡。
5. 用户可以拖动鱼缸窗口。
6. 用户可以调整窗口大小。
7. 窗口移动或调整大小时，鱼的位置能够合理调整。
8. 关闭程序后不产生后台残留进程。

## 4.2 小鱼自主行为

初始版本创建三条不同的小鱼。

不同小鱼拥有不同的行为参数：

| 属性 | 小鱼 A | 小鱼 B | 小鱼 C |
|---|---|---|---|
| 速度 | 慢 | 中 | 稍快 |
| 行为 | 缓慢游动 | 随机游动 | 喜欢改变方向 |
| 活动范围 | 全鱼缸 | 全鱼缸 | 全鱼缸 |

行为要求：

- 随机改变游动方向。
- 速度不能突然大幅变化。
- 转弯应该有平滑过渡。
- 不要长时间贴着边界运动。
- 不允许卡在角落。
- 不允许原地无限旋转。
- 不允许鱼之间频繁重叠。
- 可以偶尔相互靠近或短暂跟随。
- 每条鱼的行为应有一定随机性，不能像机械同步运动。

可以通过简单的随机游走、速度变化和状态机实现，不需要 AI 模型。

鱼缸内部的边界碰撞需要有合理处理。当边界关闭时，小鱼应自然转向，而不是突然消失或瞬移。

## 4.3 气泡和海草

气泡：

- 从鱼缸下方或随机位置产生。
- 缓慢向上移动。
- 到达顶部后消失。
- 出现频率较低。
- 不要过度影响鱼的注意力。

海草：

- 使用字符组成。
- 固定在鱼缸底部。
- 具有简单的轻微摆动。
- 不需要复杂碰撞检测。

这些元素主要是营造生态氛围，不要让开发工作过度复杂。

## 4.4 边界打开：最重要的功能

这是整个项目的核心功能。

鱼缸边界关闭时，小鱼只能在鱼缸内部活动。

用户打开边界后：

1. 边界进入开启状态。
2. 小鱼可以靠近鱼缸边缘。
3. 小鱼能够实际穿过边界。
4. 小鱼离开鱼缸后，颜色逐渐出现。
5. 小鱼进入透明桌面层。
6. 它们能够在电脑桌面的活动区域内自由游动。

必须注意：

**鱼缸窗口应该继续存在。**

鱼缸不会因为小鱼逃出来就消失。已经离开的鱼在桌面上活动，尚未离开的鱼仍然可以在鱼缸内部活动。

鱼的运动状态必须连续。不能通过隐藏原来的鱼，再在桌面随机生成一条新鱼来代替。

边界开启后，可以允许小鱼自由进出鱼缸。

## 4.5 桌面透明悬浮层

这是项目第二个关键功能。

开启边界时，程序需要创建或显示一个透明的桌面宠物层。

要求：

- 覆盖主显示器的主要桌面活动区域。
- 背景完全透明。
- 小鱼始终保持在其他普通应用窗口上方。
- 不显示额外的白色背景。
- 不遮挡任务栏。
- 不影响其他软件的正常使用。
- 不应该因为透明窗口而拦截整个屏幕的鼠标和键盘输入。
- 退出桌面模式时，正确关闭或隐藏透明层。

特别注意鼠标穿透问题：

透明桌面窗口不能一直拦截用户点击其他软件的操作。

需要研究 Windows 下透明置顶窗口的鼠标命中测试机制，并实现合理的点击穿透。

如果无法在第一版中实现精细的“只有小鱼区域接收鼠标事件”，可以增加一个明确的「捞鱼模式」：

- 默认情况下，桌面宠物层不拦截鼠标。
- 用户主动开启捞鱼模式后，允许与小鱼交互。
- 结束捞鱼模式后，恢复鼠标穿透。

不要为了实现捞鱼而让整个透明窗口永久拦截鼠标。

## 4.6 捞鱼功能

用户可以使用鼠标捞鱼。

基础要求：

1. 在桌面模式下开启捞鱼模式。
2. 点击并拖动一条小鱼。
3. 小鱼跟随鼠标移动。
4. 将小鱼拖回鱼缸内部。
5. 松开鼠标后，小鱼成为鱼缸中的鱼。
6. 小鱼恢复黑白状态。

交互反馈尽可能轻量。

后续可以增加小鱼的躲避行为，但第一版先保证拖动和归缸稳定。

## 4.7 关闭边界：自动回缸

当用户关闭边界时：

1. 系统停止产生新的外游行为。
2. 所有在桌面外部的小鱼逐渐向鱼缸移动。
3. 小鱼通过鱼缸边界进入鱼缸。
4. 重新变为黑白字符。
5. 桌面悬浮层在所有鱼回缸后关闭。

不允许直接将所有小鱼瞬移回鱼缸。

如果用户连续切换边界状态，需要保证状态不会混乱。

## 4.8 暂停功能

用户可以暂停所有活动。

暂停后：

- 小鱼停止移动。
- 气泡停止上浮。
- 动画停止。
- 恢复后从原来的状态继续。

暂停不能重置鱼的位置。

# 五、技术方案

## 5.1 推荐技术栈

优先采用：

| 模块 | 技术 |
|---|---|
| 桌面程序框架 | Tauri 2 |
| 前端 | HTML + CSS + JavaScript |
| 动画 | Canvas 或 DOM |
| 样式 | 原生 CSS |
| 桌面窗口管理 | Tauri Window API + 必要的 Windows 原生接口 |
| 后端 | Rust（仅用于桌面窗口和系统功能） |
| 数据保存 | 本地 JSON |

不使用：

- React
- Vue
- Electron
- 云端数据库
- 在线服务器
- 账号系统
- 第三方在线 API
- 在线图片资源

除非遇到明确的技术障碍，否则不要随意更换技术栈。

## 5.2 窗口设计

至少需要合理管理两个视觉区域：

**窗口 A：鱼缸窗口**

- 普通独立窗口。
- 白色背景。
- 显示文本鱼缸和内部小鱼。
- 保持可见。
- 允许用户操作控制按钮。

**窗口 B：桌面透明窗口**

- 透明背景。
- 置顶显示。
- 显示已经游出鱼缸的小鱼。
- 不应该遮挡其他软件的正常交互。
- 能接收必要的鼠标交互。

可以采用其他更合理的窗口架构，但必须保证两个世界之间的视觉连续性。

## 5.3 坐标系统

需要建立统一的世界坐标。

鱼在鱼缸中的位置需要能够转换成桌面屏幕坐标。

例如：

- 鱼缸左上角在屏幕的位置为 `(tankX, tankY)`。
- 鱼在鱼缸内部的位置为 `(fishX, fishY)`。
- 对应桌面坐标为 `(tankX + fishX, tankY + fishY)`。

注意处理：

- 窗口位置变化。
- 窗口大小变化。
- 屏幕分辨率。
- Windows 显示缩放比例。
- 屏幕边缘。
- 鱼缸窗口坐标与桌面坐标的转换。

第一版只要求稳定支持主显示器。多显示器支持可以留到后续版本。

## 5.4 运动引擎

使用 requestAnimationFrame 或其他合适的动画调度方式。

要求：

- 基于时间差计算移动，而不是简单地每帧固定移动像素。
- 不依赖固定 FPS 才能保证鱼的速度。
- 使用平滑速度过渡。
- 鱼的逻辑状态和绘制逻辑分开。
- 尽量避免每一帧创建大量临时对象。
- 限制不必要的重绘。
- 页面失去焦点或程序暂停时能够合理降低资源消耗。

建议把鱼设计为具有独立状态的对象。

例如：

```js
{
  id: "fish-01",
  x: 200,
  y: 180,
  vx: 20,
  vy: 5,
  speed: 25,
  direction: "right",
  color: "#D98B4B",
  state: "inside"
}
```

这只是参考数据结构，可以根据实际架构调整。

## 5.5 程序状态管理

必须建立明确的状态管理机制。

推荐模式：

- `TANK_CLOSED`：鱼缸关闭边界。
- `TANK_OPENING`：边界正在开启。
- `OCEAN_OPEN`：桌面海洋模式。
- `TANK_RETURNING`：小鱼正在返回鱼缸。
- `PAUSED`：暂停。

每条鱼也应具有自己的状态：

- `inside`：鱼缸内部。
- `crossing`：穿越鱼缸边界。
- `outside`：桌面区域。
- `returning`：正在回缸。
- `dragging`：被用户拖动。

请防止状态冲突，例如：

- 桌面模式还没启动就开始生成桌面鱼。
- 鱼已经回缸却仍然显示在桌面上。
- 关闭边界后仍有新鱼逃出。
- 连续点击边界按钮造成重复创建窗口。
- 暂停后仍然有动画继续运行。

# 七、开发阶段与执行顺序

请严格按照以下阶段开发。

## Phase 0：环境与技术验证

任务：

1. 检查当前电脑的开发环境。
2. 确认 Node.js、Rust、Cargo 等必要环境。
3. 确认 Tauri 2 能够正常运行。
4. 阅读当前版本的官方文档。
5. 验证 Windows 下透明、置顶窗口。
6. 验证鼠标穿透和交互的可行性。
7. 验证多个窗口之间的通信。

重点：

**不要一开始就开发完整桌面宠物。**

先制作一个最小测试程序，确认能够创建一个透明的桌面悬浮窗口，而且不会影响其他窗口的鼠标操作。

如果某项技术能力不能直接实现，需要记录具体限制和替代方案。

交付：

- 环境检查报告。
- 技术可行性报告。
- 最小透明窗口测试程序。
- 发现的问题和技术决策。

## Phase 1：完成基础鱼缸

这是第一个必须能够独立运行的版本。

任务：

1. 创建白色鱼缸界面。
2. 绘制三条不同字符造型的小鱼。
3. 实现小鱼自主游动。
4. 实现方向切换。
5. 实现速度差异。
6. 实现海草。
7. 实现气泡。
8. 实现鱼缸边界碰撞。
9. 实现暂停和继续。

此阶段不需要桌面透明层。

验收标准：

- 页面视觉符合黑白文本设计。
- 三条鱼能够持续自主游动。
- 鱼不会穿出边界。
- 鱼不会长时间卡在角落。
- 不会发生明显的原地抖动。
- 动画自然流畅。
- 程序能够持续运行。

**Phase 1 必须先完成并测试通过，再进入下一阶段。**

## Phase 2：桌面透明悬浮层

任务：

1. 创建透明的桌面窗口。
2. 实现窗口置顶。
3. 实现鼠标穿透。
4. 实现捞鱼交互所需的鼠标事件。
5. 保证桌面窗口不遮挡任务栏。
6. 实现桌面鱼的独立绘制。
7. 验证与普通 Windows 软件的兼容性。

验收标准：

- 桌面透明层没有白色背景。
- 可以看到彩色小鱼。
- 小鱼可以出现在其他应用窗口上方。
- 其他软件依然能够正常点击和操作。
- 开启交互模式后可以准确选中小鱼。

## Phase 3：鱼缸与桌面之间的自由切换

任务：

1. 建立统一的鱼的位置和运动状态。
2. 建立鱼缸坐标到桌面坐标的转换。
3. 实现打开边界。
4. 实现小鱼游出鱼缸。
5. 实现颜色变化。
6. 实现小鱼进入桌面区域后继续游动。
7. 实现关闭边界。
8. 实现桌面小鱼逐渐返回鱼缸。
9. 实现鱼缸和透明层之间的状态同步。

验收标准：

- 鱼从鱼缸游出时没有瞬移。
- 鱼不会重复出现。
- 鱼不会消失。
- 鱼不会突然变更位置。
- 鱼进入桌面后可以保持自己的速度和方向。
- 回缸后正确恢复黑白显示。
- 多次开启和关闭边界都能够正常工作。

## Phase 4：捞鱼交互和稳定性

任务：

1. 实现鼠标选鱼。
2. 实现拖动。
3. 实现将鱼拖回鱼缸。

# 八、性能与稳定性标准

本项目不是大型游戏，不应该有不必要的性能消耗。

目标：

- 三条鱼在正常情况下能够流畅活动。
- 动画目标约为 30 FPS，设备允许时可以达到 60 FPS。
- 空闲时合理降低不必要的 CPU 占用。
- 不允许内存持续无故增长。
- 不依赖持续网络连接。
- 不允许程序启动后不断产生无用的系统进程。
- 程序关闭后应该正确释放窗口和资源。

性能数据需要实际测试，不允许只在文档中声称达标。

# 九、明确禁止的设计方向

10. 不必要的通知、音效和弹窗。

第一版应当专注于鱼本身和鱼缸边界的交互。
